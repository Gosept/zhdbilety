## Описание проекта
Сайт для покупки железнодорожных билетов. Проект состоит из 5 страниц (Frontend) и Python-сервера (Backend), который связан с базой данных SQLite. Приложение упаковано в Docker и развернуто на хостинге Render.

## Как запустить проект локально
1. Убедитесь, что установлен Python и библиотеки: `pip install -r requirements.txt`
2. В папке с проектом запустите скрипт создания базы данных: `py database.py` (создаст файл `tickets.db` и заполнит его 15 рейсами).
3. Запустите сервер FastAPI: `py -m uvicorn main:app --reload`
4. Откройте в браузере `http://127.0.0.1:8000` (теперь сервер сам раздает HTML-файлы, Live Server не нужен).

## Как запустить через Docker (ПР4)
1. Соберите образ: `docker build -t zhdbilety .`
2. Запустите контейнер: `docker run -p 8000:8000 zhdbilety`
3. Откройте в браузере `http://localhost:8000`

## Структура Базы Данных (ПР3)
База данных SQLite (`tickets.db`) состоит из 3 связанных таблиц:

**1. Таблица `users` (Пользователи)**
* `id` (INTEGER, PRIMARY KEY) — уникальный номер пользователя.
* `email` (TEXT, UNIQUE) — почта (логин).
* `password_hash` (TEXT) — зашифрованный пароль (хеш bcrypt).

**2. Таблица `routes` (Рейсы)**
* `id` (INTEGER, PRIMARY KEY) — уникальный номер рейса.
* `from_city` (TEXT) — город отправления.
* `to_city` (TEXT) — город прибытия.
* `train_number` (TEXT) — номер поезда.
* `price` (INTEGER) — стоимость билета.
* `dep_time` (TEXT) — время отправления.
* `arr_time` (TEXT) — время прибытия.
* `duration` (TEXT) — время в пути.

**3. Таблица `orders` (Заказы)**
* `id` (INTEGER, PRIMARY KEY) — номер заказа.
* `user_id` (INTEGER, FOREIGN KEY → users.id) — кто купил билет.
* `route_id` (INTEGER, FOREIGN KEY → routes.id) — на какой рейс куплен билет.
* `seat_number` (INTEGER) — номер места.

*Связи:* Один пользователь может иметь много заказов (связь 1-ко-многим). Один рейс может быть указан во многих заказах.

## Что сделано в ПР2
- **Форма обратной связи** (contacts.html): проверка полей.
- **Фильтрация каталога** (catalog.html): поиск по городам и максимальной цене.
- **Интерактивный выбор мест** (order.html): подсчет итоговой суммы.
- **Внешний API (погода)**: на странице рейса через `fetch` подгружается текущая погода (API Open-Meteo).

## Что сделано в ПР3
- **База данных (SQLite)**: 3 связанные таблицы (`users`, `routes`, `orders`), заполнена 15 рейсами.
- **Сервер (FastAPI)**: реализовано 7 обработчиков (список рейсов, один рейс, регистрация, вход, создание заказа, заказы пользователя, список пользователей).
- **Безопасность**: 
  - Пароли хранятся только в виде хеша (используется библиотека `bcrypt`).
  - Все SQL-запросы параметризованные (используют знаки `?`), что защищает от SQL-инъекций.
- **Связь Frontend и Backend**: карточки рейсов на сайте генерируются динамически на основе данных, полученных с сервера (через `fetch`).

## Что сделано в ПР4
- **Docker**: создан `Dockerfile`, приложение собирается и запускается в изолированном контейнере.
- **Хостинг**: приложение развернуто на платформе Render.com (бесплатный тариф).
- **HTTPS**: сертификат выдан автоматически платформой Render.
- **Настройки**: конфигурация вынесена (порт 8000), зависимости зафиксированы в `requirements.txt`.
